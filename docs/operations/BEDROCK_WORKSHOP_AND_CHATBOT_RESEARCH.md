## Nova Multimodal Embeddings and the actual retrieval gap

| Student question | Best first approach |
| --- | --- |
| “What does my attached sketch show?” | Keep the authorized image as input to Fast Chat. Measure visual reading accuracy and make the source link open the student's actual image. |
| “What does this readable PDF say about the interview method?” | Retrieve page-labeled text from the existing course or private-source route. Search should preserve precise labels, terminology and quotations. |
| “Find the lecture slide that shows a stakeholder map” or “Which of these sketches has this layout?” | First try page-level OCR and captions on known gaps, then compare a visual embedding index when layout or similarity matters. Send the found authorized page image or its extract to the generator, with a stable page/source citation. |

The private upload path currently uses extracted text and local chunk ranking. Uploaded image sources skip text chunk ranking and can be projected as vision input. PDF extraction uses the embedded text layer. The local course evaluation records 27 of 32 Week 1 PDF pages without extractable text, with material recall@4 of 91/94 and page recall@4 of 79/94 as regression floors. Those results describe `OfflineCourseSearch`. The production Managed Knowledge Base still needs a targeted page-recall check before attributing the same misses to it. [File processing](../../backend/file_processing.py) · [Image projection](../../backend/sources/projection.py) · [Student upload retrieval](../RAG_ARCHITECTURE.md#student-upload-rag) · [Course recall results](../RETRIEVAL_EVAL.md#real-pdf-recall-floor-and-the-banner-prefix-fix-readiness-audit)

Nova places text, images, document images, audio and video in one vector space. This lets a text description find an image or lets one image find a visually similar indexed asset. An embedding selects candidates. The coach still needs to inspect the returned text or image to explain it, cite it, or abstain. The raw request schema accepts one of text, image, audio or video per request. For PDFs with diagrams or scans, AWS's example rasterizes each relevant page and embeds it as `DOCUMENT_IMAGE`, a higher detail mode, while maintaining page metadata. Pair that with extracted text or OCR when exact wording or numbers matter. [Nova embeddings guide](https://docs.aws.amazon.com/nova/latest/userguide/nova-embeddings.html) · [API schema](https://docs.aws.amazon.com/nova/latest/userguide/embeddings-schema.html) · [AWS PDF-page example](https://aws.amazon.com/blogs/machine-learning/a-practical-guide-to-amazon-nova-multimodal-embeddings/)

### Integration and alternatives

- **Direct Nova pilot.** The model is `amazon.nova-2-multimodal-embeddings-v1:0` on `bedrock-runtime`. AWS documents synchronous `InvokeModel` for small inputs and online queries, and `StartAsyncInvoke` for larger ingestion with S3 output. The model card lists commercial US East (N. Virginia) and GovCloud (US-West) without Geo or Global profiles. Oregon Mantle can remain the generation endpoint, but an Oregon application calling Nova in N. Virginia has an extra regional hop and a different processing location. Direct use supports 256, 384, 1024 and 3072 dimensions. Keep an independent index per embedding model/dimension, with a model version, document digest, page, modality and source ID on each record. [Nova model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-amazon-amazon-nova-multimodal-embeddings.html) · [Nova usage guide](https://docs.aws.amazon.com/nova/latest/userguide/nova-embeddings.html) · [AWS index example](https://aws.amazon.com/blogs/machine-learning/crossmodal-search-with-amazon-nova-multimodal-embeddings/)
- **Knowledge Base choices.** The app's production course KB is `MANAGED` and uses `managedSearchConfiguration`. AWS lists Nova under custom embedding selection for a new Managed Knowledge Base at 1024 float32 dimensions and says that selection loses the managed reranker. Its distinct native multimodal processing feature currently lists TwelveLabs Marengo Embed 3.0 as the sole model, uses text queries and returns through `Retrieve`. The customer-managed `VECTOR` KB documentation separately shows a Nova configuration in N. Virginia with image-query support. These product paths have different query shapes and storage requirements. Adding Nova as a custom embedding choice supplies insufficient evidence that the current managed course KB can do native visual search. [Repository KB adapter](../RAG_ARCHITECTURE.md#course-material-rag) · [Create a managed knowledge base](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-managed-create.html) · [Native managed multimodal processing](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-managed-native-multimodal.html) · [Customer-managed multimodal KB](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal-create.html) · [Regional and query support](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal-choose-approach.html)
- **Lower-complexity baselines.** Try existing text retrieval plus page-level local OCR or reviewed captions for a small set of visual slides. Benchmark offline lexical search as the starting point. For a cloud text index, Titan Text V2 supports Oregon, and an OCR or parsing step can preserve text from scans. AWS describes Bedrock Data Automation as a route for OCR and visual-content extraction for customer-managed KBs. For pure text-and-image similarity, the workshop's Titan Multimodal model is a comparator where supported. S3 Vectors is an option for an isolated direct pilot, with metered storage and queries and metadata filtering. Use the smallest index and service mix the experiment requires. [KB model and Region support](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-supported.html) · [AWS processing approaches](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal-choose-approach.html) · [S3 Vectors queries](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-query.html) · [S3 pricing](https://aws.amazon.com/s3/pricing/)

Treat vectors and rendered pages as derived student data and include them in deletion and rollback. Label the new index separately and keep the existing search route available while testing. Evaluate top-four material and page recall, actual support for each cited claim, abstention on missing evidence, false matches on similar diagrams, and query p50/p95 by modality. ### Cost under the S$30 target

AWS's N. Virginia price list published 2026-11-23 lists Nova on-demand embedding inputs at **US$0.135 per million text tokens**, **US$0.00006 per standard image** and **US$0.00060 per document image**. Titan Text V2 is **US$0.02 per million text tokens** in the same region. At these rates, embedding 1,000 document pages and 1,000 ordinary images once, plus 10,000 queries averaging 100 text tokens, costs **US$0.795** in embedding inference. This is an illustration of pricing units. Budget parsing or OCR, retries and reindexing, storage and vector queries, any transfer, Guardrails, AgentCore, generation and the recurring app infrastructure separately. ## Getting Fast Chat to respond sooner

The v38 smoke recorded one guarded grounded turn with 6,366 input tokens, 154 output tokens and 2.663 s to first reply text measured inside the runtime. The 80 direct Mantle calls completed successfully at p50 3.442 s, p95 32.319 s and max 42.262 s. A separate 80-session workspace-read wave through CloudFront, FastAPI and DSQL had p95 6.506 s. The slower tail is real for those scopes. Browser response paint, 80 full concurrent student generations and monthly spend still need evidence. The 80-call direct probe omitted production source retrieval, AgentCore, guardrails and saving. [Measured runs and scope](GEMMA_LATENCY_RESEARCH.md#measured-on-2026-11-24) · [Classroom capacity gate](CLASSROOM_CAPACITY_GATE.md#gemma-38-bounded-live-checks-2026-11-24)
