## Behavior and acceptance

- Coordinator moved from UI runtime to `backend/upload_queue.py`; UI keeps thin
  owner-bound adapters and compatibility imports. A locked reservation covers
  running, queued and retry-retained work before executor submission. Defaults:
  32 global/four per-owner batches, 200 MiB global/50 MiB per owner, two workers.
  Rejected work never enters the executor. Optional bounded configuration lives
  in settings and `.env.example` (`SOURCE_UPLOAD_GLOBAL_JOBS`, `OWNER_JOBS`,
  `GLOBAL_BYTES`, `OWNER_BYTES`, `RETRY_SECONDS`, all with SOURCE_UPLOAD_ prefix).
- Worker success clears original bytes and the owner-bound operation before the
  public future resolves. Public progress snapshots carry filenames, no payload.
  Completion futures contain counts only, no extracted source text. Terminal
  receipts expire and are capped at 128 global/eight per owner.
- Failures use sanitized exceptions without worker tracebacks. Original captured
  credentials are released; explicit retry captures current credentials. Failed
  batches remain charged against the same limits until removed, exhausted (three
  total attempts) or expired (300 seconds from first failure, never renewed by
  retry). An independent daemon reaps abandoned failures without browser polling.
  Active work cannot be discarded to bypass admission. Retry is owner/notebook
  scoped; terminal discard is owner scoped. A running operation that crosses its
  first-failure deadline keeps its allowance until completion, then releases it.
- Library shows persistent notebook-scoped admission messages, dismiss/reselection
  guidance, progress, bounded Retry and Remove. Failed-card polling no longer
  repeatedly raises its exception. A completion during stable-fragment rendering
  triggers one local repaint; sampled active work retains the existing polling
  remount path. Coach streaming suppresses both remounts. Already terminal jobs
  cause no repaint loop.
- Successful Sources uploads persist existing `allow_model_knowledge=false`
  behavior in WorkspaceService, before any UI revisit. Saved source selection,
  exact bytes, ownership, source availability, notebook history and text drafts
  remain intact. Chat attachments are outside this Sources queue's scope.
