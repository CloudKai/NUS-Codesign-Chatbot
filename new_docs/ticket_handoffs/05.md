## Behavior and acceptance

- Guest start validates feature flag, public origin and registered identity
  precedence, then reuses valid Guest sessions without consuming admission.
- New Guest creation reserves admission before any owner/session insert. Locked
  process-local rolling limits default to 120 starts/minute and 480/hour,
  configurable with `GUEST_STARTS_PER_MINUTE` and `GUEST_STARTS_PER_HOUR`.
  No per-IP quota; a classroom can share an address. A timestamp queue is bounded
  by the hourly ceiling, rejected attempts add nothing, and concurrent checks
  cannot overshoot. Failed creations conservatively consume reservations.
- Rejects return 429, Retry-After, no-store and no Set-Cookie. The browser shows
  the bounded wait, an explicit retry action, and lecturer-help guidance; it does
  not automatically loop or create a replacement workspace on rejection.
- Existing Guest identity/history, registered precedence, notebook/source
  isolation, renewal and feature-flag rollback contracts remain intact.
