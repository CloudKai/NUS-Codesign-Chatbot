## Acceptance evidence

- Shared lifecycle: both clients use the same dispatched worker, typed progress,
  ephemeral validated preview, durable `done`, and safe terminal error contracts.
  `started` means dispatched, not saved, and now occurs after starting the worker.
  HTTP additionally emits its existing graph event after saving.
- Exact recovery: additive authenticated
  `GET /api/v1/threads/{thread_id}/coach-turn?idempotency_key=...` returns the
  exact saved turn or null. It never generates. Ownership is checked before
  lookup. Unknown/failed/revoked keys cannot resolve to unrelated history.
  Typed client and workspace facade expose `completed_turn`; UI recovery uses
  that identity and checks saved output before timeout. Lookup outages eventually
  unlock through the existing timeout while preserving retry-key handling.
- Resource bound: the non-interrupting graph no longer retains intermediate
  LangGraph checkpoints. The 30-turn test retains zero completed checkpoints;
  70 notebooks retain at most 64 latest summaries. Saved graph output is read
  from transcript persistence after eviction/restart. No full request/source
  payload is cached as a graph checkpoint.
- Error cleanup: cleanup runs inside the accepted execution lease. Conflicting
  rejected requests and eviction of a summary cannot remove an executing turn's
  unconsumed memory/research/review data. Provider handoff data is released on
  success/failure; failed saves never produce `done` or a recovered saved turn.
- Disconnects: deterministic client tests close after dispatch and preview.
  A separate real HTTP socket smoke closed after each event, recovered using the
  exact key, retried, and found exactly one saved user/assistant pair.
- Restart: reopening disposable SQLite and a new application returns exact saved
  output. The real local server was restarted with the same disposable database;
  the browser retained its saved conversation.
