### What a student sees on a parse failure (production path, file and line evidence)

1. **First cycle forces tool use.** The runtime's first cycle forces tool use for `fast_chat`: `_install_first_cycle_structured_output` sets `tool_choice={"any": {}}` (`agentcore_runtime/main.py:381-461`).
2. **One recovery turn inside the invoke.** Strands gets the structured-output model and the repair prompt "Please use the output tool now." (`agentcore_runtime/structured_coach.py:76`). It also gets `limits={"turns": 2}` (`FAST_CHAT_INVOKE_LIMITS`, `structured_coach.py:90`; `structured_output_limits_for_role`, `:592-610`). That allows one generation plus at most one recovery turn (docstring `main.py:510-520`, call `main.py:625-629`). Throttle retries are a separate mechanism (`FAST_CHAT_MODEL_RETRY`, `max_attempts=2`, `structured_coach.py:241-243`). Strands is not installed in the backend venv, so I read this recovery behaviour from the code and its docstrings and did not execute it.
3. **The runtime fails closed.** If the output still does not parse, `structured_from_agent_result` raises `CoachTurnExtractionError("structured_output_failure")` (`structured_coach.py:1242-1291`). The runtime then returns `{"ok": false, "error": true, "category": "structured_output_failure"}` (`main.py:653-689`; `harness_error_payload`, `structured_coach.py:937-950`).
4. **The backend re-invokes once.** `_raise_if_harness_error_envelope` maps the envelope to a transient malformed error (`backend/agentcore_provider.py:377-403`, `:284-299`). `_assess_fast_chat` then makes one fresh stateless re-invoke (`agentcore_provider.py:2106-2134`) within the budget `FAST_CHAT_MAX_PROVIDER_INVOCATIONS_PER_TURN = 2` (`backend/settings.py:75`; check `:314-330`). A reply that parses but fails `_validated_fast_chat` (`:1001-1027`) is not retried (`:302-311`).
5. **After both invokes fail.** The backend raises `ProviderUnavailableError("The coach reply could not be completed", category="structured_output_failure")` (`agentcore_provider.py:102`). The stream sends `{"event": "error", "status": 503, ...}` (`backend/coaching/streaming.py:29-31`), and the non-stream path returns a 503 (`backend/http/app.py:117-122`). No assistant turn is saved, and the same idempotency key can be retried (tests `tests/domain/test_agentcore_provider.py:1187-1216`, `:1249` onwards).
6. **What the student sees:**
   - React pilot UI: "The answer was not confirmed saved. Your question is kept. Check saved answer before retrying." (`frontend/src/Conversation.tsx:217`), with a "Check saved answer" button (`:404`).
   - Streamlit: "The coach couldn't complete that reply. Please try again." (`ui/panels/chat.py:328-329`).
   - No `needs_sources` second call runs, because `_maybe_rag_fallback` only runs after a successful first result.

**Eval vs production.** The eval makes one Converse call with forced `toolChoice: {"any": {}}`. It has no recovery turn, no fresh re-invoke and no SDK retry (`LiveFastChatBridge`; `total_max_attempts: 1`), and it counts a reply without a valid tool call as a failure. Production allows up to 2 generations per invoke and 2 invokes per turn before the student sees the error. **So the eval's 11/295 is an upper bound on the student-facing failure rate, not a measurement of it.** The production path is pinned by existing tests: `pytest tests/domain/test_agentcore_provider.py -k "harness or structured_output"` gave 12 passed (script run).

### Extra prompt tokens per turn (estimates)

The gate rows hold file names, not file text, so no search can run offline. Instead, for each fired row the script builds two requests through the real `AgentCoreCoachProvider._invoke_payload`, with a client that raises if called:
- the request production would send without the policy;
- the same request with `min(4, 2 × uploads)` full-size chunks (1,800 characters each, the `LocalChunkRetriever` defaults), formatted by the production `bounded_retrieval_result` within `FAST_CHAT_RETRIEVAL_MAX_CHARS=8,000`.
