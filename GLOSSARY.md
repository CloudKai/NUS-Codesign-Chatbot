# Student learning companion

Shared educational language for lecture help and student-led design development.

## Language

**Lecture help**:
A direct answer to a course-content question, supported by available course
evidence. Using lecture help alone does not imply an attempt to complete a project stage.

**Project coaching**:
Guidance that helps a student develop and explain their own design reasoning
through the five Thinking Path stages.

**Working problem statement**:
A student-authored description of affected people, their problem or context,
and a meaningful desired outcome, open enough to support idea generation.
It can be refined as evidence develops; exact “How might we” wording is not required.
_Avoid_: Final problem statement

**Stage recommendation**:
The coach's proposal to stay in the current stage or proceed, with a reason.
It is distinct from the student's confirmation to move.

**Stage confirmation**:
The student's explicit acceptance of a recommended move to the next stage.

**Stage revisit**:
A student's return to a previously completed stage to review or refine their
work. It does not require another first-time advancement recommendation.

**Thinking Path**:
The five-stage project journey: Problem identification, Concept generation,
Design specification, Ethics & Critical Thinking, and Reflection.
_Avoid_: Studio

**Review**:
A summary of a student's design reasoning and progress, with strengths, areas
for improvement, and Facione feedback when available.

**Saved work**:
Student contributions and related coach summaries and feedback collected by
Thinking Path stage.

**Notebook sources**:
Reference materials shared across the chats in a notebook. A message attachment
is a file the student includes with an individual chat message.
